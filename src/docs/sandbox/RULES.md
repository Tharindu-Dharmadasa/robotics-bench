# Robotics Bench — Engineering & Simulation Rules

## 1. Visual & HUD Rules

1. **Blueprint & Workbench Aesthetic:** Preserve the existing Robotics Bench look—crisp technical panels, monospace indicators, `FIG. XX` module headers, and clear status badges (`POWER ON/OFF`, `READY`, `FAULT`, `BURNT`).
2. **Power-Off Assembly:** Users can add, move, rotate (`90°` steps on breadboard), wire, and unwire components freely while `powerEnabled` is `false`. Turning power on energizes MCU/supply rails and evaluates active circuit behavior and faults.
3. **Animated Current Flow When Powered On:** When `powerEnabled` is `true`, render directional current flow pulses (`CurrentFlowOverlay`) from higher potential/source toward lower potential/sink along active conductors and components, colored by role (`POWER`, `SIGNAL`, `FAULT`) and paused when powered off or paused.

## 2. State, Undo/Redo & Persistence Rules

4. **Commit-Based Topology & Undo Scope:** Keep in-flight drag positions, wire previews, `powerEnabled`, live `inputStates` (potentiometer dials, pushbuttons, sensor distances), and manual GPIO overrides in transient `draftStore`. Commit to `useSandboxStore` only on pointer-up or wire finalization. Configure `zundo` with `partialize` so undo/redo tracks only `{ placedComponents, wires }`.
5. **Single Source of Truth for Placement & Grid:** Represent placement via discriminated `ComponentPlacement` (`DESK` vs. `BREADBOARD` with `anchorHole` and `quarterTurns`) and derive hole occupancy and pin addresses via `breadboardGrid.ts`—never persist stale `snappedPinMap` or duplicate coordinates. Moving a breadboard moves its mounted parts; deleting a breadboard detaches mounted parts to `DESK` and prunes invalid wires.
6. **Burnout & Overload Latching Lifecycle:** Track `burntInstanceIds`, `latchedOverloadIds`, and `damagedPinAddresses` inside the simulation engine/worker (see ARCHITECTURE §5.6.2). Never persist them in saves or share URLs. Keep `burntInstanceIds` and `latchedOverloadIds` latched across net rebuilds while the damaged or overloaded component remains in `snapshot.components`; clear an entry only when `resetFaults()` is called or when that `instanceId` is removed from the topology (and pruned when its deletion is committed, so Undo of a deletion restores an intact part).
7. **Validated Persistence & Safe Identifiers:** Forbid `:` in all IDs (`/^[a-zA-Z0-9_-]+$/`). Include `schemaVersion` and `calibratedModelVersion` in saves, validate decoded share URLs with `zod` and strict array size caps, run a `validateTopologyIntegrity` pass verifying every `defId`, `boardId`, `HoleCoord` (`col` and `row` bounds for `BreadboardRegion`), and `pinId` exists before touching store or worker state, and surface a warning if a loaded component's `calibratedModelVersion` differs from `ComponentDef.modelVersion`. Enforce the limits in ARCHITECTURE §5.6.10 (`MAX_COMPONENTS`, `MAX_WIRES`, compressed/decompressed length caps, finite numbers, hex wire `color`, `.strict()` schemas) before and after decompression and before any parse reaches the store or worker.

## 3. Simulation & Worker Rules

8. **Off-Main-Thread Simulation & Import Boundaries:** Run DSU net building, DC nodal solving, fault evaluation, and `dt` accumulation off the main thread in `src/simulation/worker.ts`. Enforce ESLint `no-restricted-imports` patterns (`**/simulation/unionFindNetlist*`, `**/simulation/dcNodalSolver*`, `**/simulation/faultValidator*`, `**/simulation/behavioralEngine*`) across `src/components/**`, `src/store/**`, and `src/utils/**`, and forbid `react` and `three` imports inside `src/types/**`, `src/registry/**`, `src/simulation/**`, `src/utils/breadboardGrid.ts`, `src/utils/manifestValidation.ts`, and `src/utils/wireValidation.ts`. Drop any `SimulationFrameOutput` whose `topologyEpoch` does not match the active topology epoch. Additionally forbid imports of `**/store/**`, `**/components/**`, `zustand`, `zundo`, and `idb-keyval` inside `src/types/**`, `src/registry/**`, and `src/simulation/**`.
9. **Comlink Callback Proxying:** Never pass raw JS functions across `postMessage`; `EngineClient` must wrap `onFrame` and `onError` listeners with `Comlink.proxy(...)`, return synchronous unsubscribe functions, and explicitly unsubscribe/release stored proxies on cleanup and `dispose()` so worker-side proxies do not leak. Unsubscribe functions must be safe to call before the worker subscription id resolves; `init()` and `dispose()` are idempotent; the engine client lives outside React; and `setInputState` calls are coalesced latest-wins per animation frame (ARCHITECTURE §5.6.9).
10. **Three-Tier Invalidation & Per-Tick Order:**
    - Rebuild DSU nets strictly over zero-resistance conductors (wires, breadboard strips/rails, internal pin groups) only on committed topology changes (`loadTopology`). Keep closed `SWITCH` contacts as resistive branches (`contactOhm`) rather than DSU merges so Tier 2 `setInputState` updates do not rebuild DSU nets.
    - Re-solve cached nets on `setPower`, `setInputState`, `setManualPin`, or `loadProgram` (keying implicit MCU `5V`/`3.3V` rail activation on `def.model.kind === "MCU"`).
    - Advance simulated time (`simTimeSec`) inside the worker through a pure `step(dtSec)` core driven by a non-`requestAnimationFrame` timer (`setInterval`/`MessageChannel`): clamp raw `dt <= 0.05s`, apply the speed multiplier, then run a fixed-step accumulator with `FIXED_DT_SEC = 1 / 60` and `MAX_SUBSTEPS = 8`, in exact order: program/manual pins → pin drive states & H-bridge/ultrasonic models → DC/LED solve & current flows → sensor/button input sampling (explicit 1-tick feedback latency) → `I^2 * t` / `0.2s` sim-time timers and fault latching.
11. **Non-Singular Finite-Resistance Solver:** Give every voltage source, MCU rail, and active GPIO pin finite internal resistance (`internalOhm`). Clamp every resistive edge to `MIN_OHM`, use `GMIN` for open elements, and clamp the potentiometer wiper fraction. Determine floating islands topologically (`voltage = null`, flagged by `netFloatingMask`), use the ground-reference rules in ARCHITECTURE §5.6.3, and cap piecewise-linear LED state iterations at `8` per solve (keep the last state and set `converged = false` if the cap is hit).

## 4. Electrical & Fault Rules (Phase 1)

12. **Dead Short (`DEAD_SHORT`) & Overload Latching:** A zero-resistance path between an active positive source/rail and `GND`, or a solved external loop resistance `<= SHORT_OHM` while the source exceeds its rating, emits `DEAD_SHORT` and latches that source's overload state (cutting its regulated output) until `resetFaults()` is called or the source is removed from the topology (consistent with Rule 6)—preventing tick-by-tick oscillation while the short remains wired.
13. **Rail & GPIO Contention (`RAIL_CONTENTION`, `GPIO_CONTENTION`):** Connecting two unequal voltage rails on one net (including back-feeding an implicitly powered MCU `5V`/`3.3V` rail) emits `RAIL_CONTENTION`. Driving `HIGH` and `LOW` simultaneously on the same net via `GPIO` pins emits `GPIO_CONTENTION`.
14. **Polarity, Over-Voltage, LED Overcurrent & Pin Overcurrent:** Specify `I^2 * t` (`i2tLimitA2s`, falling back to `DEFAULT_I2T_FACTOR_S * (maxCurrentMa / 1000)^2`, accumulating only the excess over rated current) and `maxCurrentMa` / `imaxMa` on the LED model and `GPIO`/`POWER_OUT`/`POWER_IN`/`GND` pin definitions, and evaluate overlapping faults in deterministic precedence order (`DEAD_SHORT` → `RAIL_CONTENTION` / `GPIO_CONTENTION` / `REVERSE_POLARITY` → `OVER_VOLTAGE` → `LED_OVERCURRENT` / `PIN_OVERCURRENT`), breaking ties within a level by `FAULT_ORDER`, then `instanceId`, then pin address. A higher-precedence fault suppresses lower-precedence faults on the same net or instance (ARCHITECTURE §5.6.2):
    - Reversed LEDs block forward conduction; reversed polarized supplies and `POWER_IN` pins (`polarized !== false`) emit `REVERSE_POLARITY`; non-polarized parts never do.
    - Pin voltage exceeding `maxVoltage` emits `OVER_VOLTAGE` and latches the affected component burnt.
    - Forward LED current exceeding `imaxMa` (or accumulated `I^2 * t` limit) emits `LED_OVERCURRENT`, flashes for `0.2s` of simulated time, and latches `burnt`.
    - Current exceeding `maxCurrentMa` on a `GPIO`, `POWER_OUT`, `POWER_IN`, or `GND` pin (such as `GPIO HIGH -> GND`, an unresisted `5V -> LED -> GND` source pin, or a stalled actuator) emits `PIN_OVERCURRENT` and latches overload/burnout.
15. **Mode-Aware Floating Pin & Guided Pinout Rules:** Emit `FLOATING_PIN` only when an MCU input pin (`ANALOG_IN`, or `GPIO` in `INPUT` mode) referenced by the active program, or a device `SIGNAL_IN` pin with `requiredDriven: true` while powered, sits on an undriven net without pull-up/pull-down. Every pre-built program must declare its pin contract via `ProgramMeta.pinRequirements` (`src/types/program.ts`) and support `ManualPinOverride` controls so the UI can show pin badges and highlight valid targets.

## 5. 3D Rendering & Resource Rules

16. **Wire Validation & Geometry Cache:** Reject self-connections, duplicate wires on the same endpoints, and multiple wire leads in the same breadboard hole. Cache procedural wire `THREE.TubeGeometry` outside Zustand in `Map<string, THREE.TubeGeometry>` and recompute routes using post-rotation world AABBs whenever a topology commit moves or adds obstacles. During drags, redraw attached wires live as simple curves from `draftStore` positions; recompute full routes and the cache only on commit.
17. **Analytic Hit-Testing, Instancing, Depth Precision & Disposal:** Configure the Three.js renderer with a standard 24-bit depth buffer, `camera.near = 0.002`, `camera.far <= 20`, `polygonOffset` on coplanar surfaces, and hit/snap radii scaled proportionally to `pitchMeters` so millimetre-scale components neither clip nor lose depth precision; enable `logarithmicDepthBuffer` only if a spike proves it necessary. Hit-test breadboard holes analytically via `breadboardGrid.ts` rather than per-hole colliders. Use `InstancedMesh` for animated current-flow pulses and smoke particles. Clone materials per module instance before applying scorch/glow uniforms, and dispose only dynamically created sandbox geometries/materials—never shared cached `.glb` assets. Lock `OrbitControls` during drags/wire routing and verify frame budgets via `renderer.info`.

## 6. Timing, Lifecycle & Transport Rules

18. **Analytic Timing & Program I/O:** The `1/60 s` tick is behavioral. Servo pulse width and ultrasonic echo timing are computed analytically (ARCHITECTURE §5.6.6). Programs read only `readDigitalIn`, `readAnalogIn`, and `pulseInUs`; PWM writes carry `freqHz`. No program may read button or sensor state directly.
19. **Power & Time Lifecycle:** `setPower(true)` resets program runtime and `simTimeSec`; `setPower(false)` zeroes net state and keeps latched faults; `pause()` freezes time only (ARCHITECTURE §5.6.7).
20. **Typed-Array Frame Transport:** `loadTopology` returns a `TopologyDescriptor` once per commit. Per-tick frames contain only typed arrays plus change-only events, sent with `Comlink.transfer`; the main thread keeps only the latest frame. Floating nets use `netFloatingMask`, never `NaN`.
